## Goal
Connect the frontend booking form to the existing Rust/Axum backend at `http://127.0.0.1:8090`. This requires changes to both the backend (CORS + unique constraint) and the frontend (form fields + API calls).

## Backend changes (`mypath-backend/`)

### 1. Add CORS middleware
- Add `tower-http` crate with `cors` feature to `Cargo.toml`
- Add a `CorsLayer` in `src/main.rs` allowing the frontend's origin (any local origin for dev: `http://127.0.0.1:*` and `http://localhost:*`)
- This allows the browser to make `fetch()` calls from the HTML file to the backend

### 2. Fix UNIQUE constraint
- In `src/db.rs`, change `CONSTRAINT unique_booking_datetime UNIQUE(booking_date, time_slot)` → `CONSTRAINT unique_booking_datetime UNIQUE(booking_date, time_slot, room_name)`
- This allows both rooms to be booked at the same date+time without 409 conflicts

## Frontend changes (`quorum-meeting-room_v2.html`)

### 3. Add "Meeting topic" field to step 4 form
- New `<input id="fTopic">` field alongside name, email, phone in the booking form
- Marked required, with placeholder "What's the meeting about?"

### 4. Add API base URL config + helper function
- New `API_BASE` variable at top of booking script (defaulting to `http://127.0.0.1:8090`)
- Helper `slotFormat(hour)` that converts the JS 24h hour (e.g. 9, 14) to the backend's expected `"09:00-10:00"` / `"14:00-15:00"` format
- Helper `guestWord(n)` that maps a number to the backend's enum strings: 1→"One", 2→"Two", … 8→"Eight"

### 5. Replace `confirmBtn` handler with real API call
- When user clicks "Confirm booking":
  - For each selected room, send a separate `POST /meeting/book/add` with:
    ```json
    {
      "date": "YYYY-MM-DD",
      "organizer_name": "first last",
      "topic": "from form",
      "contact": "phone number",
      "time_slot": "HH:MM-HH:MM" (for each booked hour),
      "room_name": "8 Seater" or "Premium 4 Seater",
      "attendees": "One"-"Eight"
    }
  ```
  - One POST per room per time slot (since each row in the DB is one booking for one slot)
  - Handle 201 (success), 409 (already booked → show "slot taken" error for that room), 500 (server error)
- Only show the success state if ALL posts succeed
- Show a specific error message if any slot is already taken (409 conflict)

### 6. Handle errors gracefully
- Add an error state to the confirm step (red message near the button)
- On 409: "This time slot is already booked. Please choose a different time."
- On 500: "Something went wrong. Please try again."
- On network error: "Could not reach the server. Is the backend running?"

### 7. Disable confirm button during submission
- Set `confirmBtn.disabled = true` and change text to "Booking…" while API calls are in-flight
- Re-enable on completion or error
